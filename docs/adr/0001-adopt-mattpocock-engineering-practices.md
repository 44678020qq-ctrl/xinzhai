# ADR-0001: 采用 mattpocock/skills 工程实践

## 状态

已采纳（2026-05-25）

## 背景

心斋项目从 05-19 创建到 05-23 经历了6个批次18个工单的快速迭代，积累了大量技术债：
- 注册页真太阳时边界 bug 导致核心链路不通
- 多处降级链缺乏统一调试方法
- 代码库术语混乱（八字术语 vs 用户文案 vs 代码变量）

## 决策

引入 mattpocock/skills 的三个核心实践：

1. **CONTEXT.md 共享语言** — 项目术语表，消除歧义
2. **diagnose 调试法** — 先建反馈循环再猜原因，6步结构化调试
3. **ADR 决策记录** — 硬决策记录（难逆转+需上下文+真实权衡）

## 后果

- 所有后续代码阅读先查 CONTEXT.md 术语
- Bug 排查遵循 diagnose 6步法（建循环→复现→假设→探测→修复→清理）
- ADR 仅在三个条件同时满足时创建（难逆转/无上下文会困惑/真实权衡）
